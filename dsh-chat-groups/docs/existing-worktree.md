# Chat Groups · 新会话选择已有工作树

已在插件源码实现，目标运行时为 DSH 0.2.2-rc.5。下列设计及验收目标的实测范围见末节。

## 使用流程

从官方「新建会话」或 Chat Groups 分组的「＋」进入原生空白会话。输入框上方、官方分支信息旁显示「工作树 ▾」。默认项为「工作区默认目录」。展开时显示同一 Git 仓库已检出的工作树，每项显示分支和路径，分离 HEAD 显示短提交号。使用默认目录时，仅在有其他可选工作树时显示入口。已经选过工作树的会话可以切回默认目录，即使当前列表为空。

选中工作树后在当前页应用，确认成功后显示选中项。用户可以先输入草稿再选目录，也可以在首次发送前切回默认目录。正常发送后收起入口。如果首轮被工作树校验拦截，输入框旁会出现「重新选择工作树」。从分组进入时，会话继续属于该分组。选择仅对这一个会话生效。

## 实现

1. **两个入口共用一个选择器。** 客户端向 `conversation.hero.options` 注册控件，以插槽提供的 `sessionId` 绑定选择。分组沿用现有新建并打开原生会话的流程。控件独立于侧栏视图开关。
2. **由 Host 枚举并校验。** 从会话所属工作区定位仓库，用 `git worktree list --porcelain -z` 枚举登记项，过滤 bare、已缺失等不可用项。使用规范化路径区分工作树。每次应用均复核用户权限、会话归属、目标仍登记且可访问、会话仍允许更改。仓库查询以原工作区为基准。
3. **沿用当前会话。** 优先验证通过 `ctx.workingDirectory.set` 设置会话有效目录。以原生目录投影作为选中值，刷新或重新打开时重新读取。保留原会话 ID、草稿、工作区及分组关系。目录切换与沙箱授权独立，首版仅开放能按当前会话权限用于预期操作的目标。
4. **与官方「新建工作树」协调。** 有待创建请求或正在创建时，已有工作树选择器会禁用。先选已有工作树再勾选官方选项时，Host 会撤销创建请求，客户端提示先恢复默认目录。
5. **保护首次发送。** Host 在组装系统提示和首次运行工具时校验工作树，直到首轮结束。显式切换目录成功后，后续操作使用新目录。工作树在模型执行前或首轮工具访问时失效，Host 会保存失败状态。用户可从输入框旁的恢复入口重选目录并再次发送。

分组和待使用的工作树选择存放于 `chat_groups` 存储域。格式版本 2 可读取版本 1 的已有分组。首次写入版本 2 后，旧插件打开此域会收到版本不兼容错误；重新启用新版可继续使用原数据。

## 实施与验收

| 阶段 | 检查内容 | 通过条件 |
|---|---|---|
| 接口原型 | 两个入口、草稿、首次发送 | 提前输入草稿后选择工作树，发送一次；首个工具读到目标 checkout 的专属文件，`pwd` 与规范路径一致，会话 ID 与分组一致 |
| 权限验证 | 工作区内和同仓库外置工作树 | 在测试仓库验证实际读写结果符合会话文件策略；不可用项有明确说明 |
| 状态与竞争 | 快速连选、切换中发送、双窗口、勾选顺序、目标失效 | 界面展示与实际执行目录一致，失败可重选，草稿保留，无重复会话或意外创建工作树 |
| 回归 | 刷新、切工作区、非 Git 仓库、仅主工作树、官方新建工作树 | 刷新反映真实有效目录，其他会话独立，默认新建和分组归属均按原流程工作 |

## 验证记录

在独立的 DSH 0.2.2-rc.5 Host 和临时 Git 仓库中，通过 RPC 选中工作树，首次 `read` 读到了该工作树专属的文件。发送前移除工作树时，模型调用次数为零。模型生成首个 `read` 时移走目录，工具返回错误，默认目录的同名文件没有被读取。两种情况下，在同一会话重选替代工作树并再次发送，`read` 均读到了替代工作树的文件。启用官方 Forge 后重复测试通过；首次 `read` 失败后重启 Host，也能按需恢复同一会话并切换到替代工作树。

用同版本的 JSON 存储后端验证了版本 1 的分组读取、写入版本 2、旧版拒绝打开，以及重新启用新版后分组和工作树选择的保留。客户端交互使用组件回归测试验证。独立 Host 实测使用临时 profile 的 `danger-full-access` 模式。当前 macOS 外层沙箱拒绝嵌套执行 `sandbox-exec`，因此 `workspace-write` 覆盖来自权限回归测试。当前 Desktop 配置未安装待测版本。

切换进行中，当前窗口会暂时锁定输入框。如果消息已经进入 DSH 收件箱，恢复目录后需要再次发送。
